Status vocabulary

Interface chrome is deliberately near-monochrome so that status is the only saturated colour on the page. Colour is never the sole carrier — each state also has a distinct uppercase label.

StateMeaningReachable from
Pending Accepted, not yet started. Every job's first status. Running · Failed
Running Executing now. Carries a live pulse dot. Completed · Failed
Completed Finished successfully. Terminal — no further changes. — (delete only)
Failed Terminated with an error. Terminal, but retryable. Re-run → Pending
Cancelled Called off deliberately, while queued or running. Terminal, but retryable. Re-run → Pending

Transitions are enforced by jobs/transitions.py and mirrored in the dropdown, so an illegal move is unreachable rather than merely rejected. The asymmetry at the bottom is deliberate: you retry a failure, but re-running a success isn't a retry — it's a new job.

Status control by state

C12C3

What each row offers, and what editing looks like: Edit turns the status badge itself into a select, in place — so status appears exactly once per row rather than as a badge on one side and a button on the other. Illegal transitions are disabled inside the select. A completed job says why it has no control instead of showing a dead button.
