Job Management Dashboard — UI mockup

Every state the interface can reach, with hard-coded data and no backend. This is the artifact to argue with before any React exists — changing a layout here costs minutes, changing it after slices 5–8 are wired through TanStack Query costs a rebuild of every component and its tests.

How to review: the prototype below is live — type in the search box, open a status menu, expand a history, try creating a job with an empty name, delete something. Toggle Simulate API failure to watch optimistic updates roll back.

Status vocabulary

Interface chrome is deliberately near-monochrome so that status is the only saturated colour on the page. Colour is never the sole carrier — each state also has a distinct uppercase label.

StateMeaningReachable from
Pending Accepted, not yet started. Every job's first status.any
Running Executing now. Carries a live pulse dot.any
Completed Finished successfully.any
Failed Terminated with an error.any

“Reachable from: any” is the shipped permissive policy (Q7). The status control stands in for scheduler events rather than a user workflow, so every state stays reachable; the strict map lives beside it in jobs/transitions.py.
